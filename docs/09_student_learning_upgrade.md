# 学生教学与学习闭环升级

## 本轮实际完成

继续基于产品开发版和官方 DeepTutor 固定 commit `341af371bf8143b2da3569084edf8e6cb46d7404` 实施。官方教学循环、工具规划、WebSocket 会话恢复、学习状态、记忆系统和教学界面仍直接使用上游实现。教师端、原成绩、错题归属与官方 Py-FSRS 的业务权威仍在 MindTrace，不建立重复的成绩系统。

### 官方插件发现与真实数学工具调用

发现并修复上一轮接入的实质性缺陷：官方 `get_tool_registry()` 随账户插件作用域变化重建注册表，在管理员启动作用域手动注册的工具不会可靠地出现在学生作用域。另有 grant 对延迟工具的过滤，不能以“注册代码运行成功”作为接入完成证据。

本轮改用官方 `deeptutor.tools` entry point：`integrations/deeptutor/plugin/pyproject.toml` 安装三个适配器；官方插件发现、账户注册表、grant、`build_tool_view`、`DeferredToolLoader` 和 dispatch 全部保留上游实现。

| 工具 | 实际职责 | 边界 |
| --- | --- | --- |
| mindtrace_source | 本学生当前原题、作答、教师有效反馈及订正进度 | 不传他人材料；以当前来源版本为准 |
| mindtrace_math | 直接调用原有受约束 SymPy 适配器，支持三角、对数、指数、方程、不等式、求和、向量、距离、集合等计算 | 不是完整证明器；超时/不支持不会推出学生做错 |
| mindtrace_learning_evidence | 从课堂当前有效证据重算个人画像，区分原答、辅助完成与独立验证 | 不生成未经校准的掌握概率；限制最多12个知识点、每项6条来源控制上下文 |

工具本身不拥有新的教学循环。新增的都是数据与数学库的适配器。数学工具未提供待比较答案而完成计算时，不再把“不适用正误判定”暴露成“证据不足”。通过官方 ToolPromptHints 要求面向学生解释数学结果与适用条件，避免堆砌实现状态码。

### 真正完成复习，而非仅显示数量

新学习空间提供「我的错题 / 复习计划 / 学习证据」三个连续视图，使用官方 MarkdownRenderer 渲染数学内容，关闭原始HTML和外部图片。题卡可直接进入原题辅导或加入复习；复习不再要求回到另一套界面。

复习流程为：加入计划 → 打开不展示原答案和教师解答的独立作答页 → 提交过程与答案 → 可靠参考答案核验或教师复核 → 记录实际完成难度 → 官方 Py-FSRS 计算下次复习。解答题需要过程复核时等待教师，不以字符串相同或AI自评替代过程判断。教师反馈可在同一页刷新获取；尚未调度的作答可从计划恢复查看。

`core/tutor_learning.py` 调用已有 `learning_records` 和 `review_scheduler`，没有重写 FSRS。卡片状态、ReviewLog、时间、幂等约束和失效规则仍沿用官方 `fsrs==6.3.3` 与现有业务约束。另一学生、另一复习轮次、失效题目和已使用的命令均不能更新该次计划。

### 辅导后订正与独立验证严格区分

原题侧栏已经展示教师反馈，提交一律由服务端记录为借助参考的订正；不能通过取消勾选获得“独立完成”标签。独立重做有单独的复习轮次；若本轮打开原题反馈、进入教学会话或通过工具读取答案，服务端标记本轮已使用帮助。即使客户端仍报“未使用”，也不会成为独立回忆成功。

该规则记录的是本次产品内可观测行为及学生自报，不声称能证明学生离线完全未查答案。学生提交后再查看反馈，不会倒改已保存作答的独立性；同一轮更换答案则必须新建作答轮次，不能覆盖。

提交时在课堂事务内重核来源版本，避免教师更新材料或评分依据期间接收旧依据的作答。原始答案始终保留。学习画像优先使用教师有效确认的知识点标签，修复一直沿用旧AI标签的情况。

### 官方记忆与来源同步

复习作答、正式FSRS记录和辅导后订正通过官方 `MemoryStore.emit(TraceEvent)` 写入本人原生来源追溯；不将聊天、看过答案或提交动作等同于掌握。回到原题时更新原生 notebook record 的当前订正状态；换版后旧来源记录会通过官方 `update_record()` 标记为历史失效，旧会话不能启动新轮次。

官方 L2/L3 摘要和记忆工具继续保留。当前未另外开启收费的自动批量整理任务；课堂事实的即时读取以当前证据工具为准。旧摘要的完整跨版本失效传播仍需进一步验证，不以添加一条原始 trace 声称已解决全部长期记忆问题。

## 开源复用决策的落实

| 来源 | 决策 | 理由与实际实现 |
| --- | --- | --- |
| DeepTutor | 直接接入官方运行时与界面；业务工具以官方插件适配 | 教学、状态、记忆已有成熟代码；不再重写同名简化Agent |
| Py-FSRS | 直接复用官方库 | 已有真实Scheduler/Card/ReviewLog，补齐界面和课堂关联即可 |
| Anki | 借鉴作答与复习分离的交互；不复制源码 | 数学过程核验与记忆卡片不同；避免无必要引入整套AGPL应用 |
| Auto-Homework-Grader / GradeFlow | 保留已完成的源码研究，不复制未明确许可的代码 | 按研究中的许可证证据处理；本项目已有持久后台、重试与续批，不能为“移植”破坏稳定链路 |
| Oppia | 保留状态/反馈分支设计参考；动态教学使用官方DeepTutor | 不为了规则分支引入整套重型平台或第二套教学状态引擎 |

这里的保留不等于忽视其他项目，也不是以旧代码为优先。只有当模块实际适配、许可允许、收益明确时才移植；当前教学执行已直接换成上游官方能力。

## 已执行验收

- 项目完整离线回归：369项通过，88.50秒；仅Starlette/httpx弃用提醒。
- 官方前端类型检查通过。
- 原生教学页面、教师反馈、订正回传及学生隔离：5项浏览器验证通过，不调用模型。
- 新学习首页、学习证据、无答案独立作答、教师反馈刷新、FSRS记录、服务端辅助标记、390像素手机布局、无浏览器异常：8项真实浏览器验证通过，不调用模型。
- 官方 grant → 工具池 → 加载器 → dispatch 实测通过；三项符号计算、本人资料、他人资料拒绝及无效数学输入拒绝均通过，不调用模型。
- 一次真实模型教学测试：官方Agent实际调用 `load_tools` 后调用 `mindtrace_math` 三次。分别得到 `sin(x)^2+cos(x)^2=1`、`d(log(x)-a*x)/dx=1/x-a, x>0`、`binomial(10,3)/2^10=15/128`。16.11秒完成；原生用量记录3次模型请求、60,071 token，其中53,376为缓存读入，0次估算请求。此数据不能当作价格账单，也不能与不同任务的上一轮样例比较后声称成本降低。

测试使用明确构造的匿名课堂和教师材料。教师复核部分调用真实课堂领域命令，FSRS部分实际写入原课堂库；不将这些构造记录当作真实学生学习效果或数学准确率数据。真实模型调用仅执行这一轮，没有自动重复付费试验。

## 尚不能据此声称完成的事项

- 不能根据三项计算和两轮教学样例宣称覆盖所有高中题型或所有证明的自动核验；教学讲解与形式化证明能力需要分开评估。
- 新学习空间复习已完整接通；官方原生教学页自己的其他复习策略与产品FSRS仍是不同语义，不能混作同一调度器。
- Qwen图片/PDF识别继续使用原产品已有入口；官方React原生附件入口尚未整体接到Qwen，不能宣称两个上传入口已完全统一。
- 未承诺自动L2/L3整理、生产环境运行稳定性或大规模真实手写识别准确率已达标；这些需要后续专门验证。
- 所有改动仍在本地开发版。公开Streamlit链接未更新；官方教学后端与React前端需要独立部署，单独推送Streamlit源码不足以发布此架构。
