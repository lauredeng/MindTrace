# 05｜题目身份、学习闭环与持久后台实施记录

日期：2026-11-21。范围为用户批准的连续优化：稳定题目身份、教师学生订正闭环、持久任务、证据画像、官方FSRS及对应界面。公网部署及付费模型效果评测未执行；不把工程检查解释为与其他项目的整体水平相同或保证获奖。

## 1. 题目与作业

- 保留原question_id兼容关系，新增assignment_question_id和canonical_question_id，分别用于作业内对应、跨作业学习来源。question_revision、grading_revision与原答fingerprint分离。
- 仅对确定的排版差异或一致原卷证据建立对应。不只按题号合并；相同题号不同题干、不同小问、数学符号差异继续分开。
- 教师可在「批次设置→题目对应」核对后调整关系；同一学生的两份作答不能无提示合并。历史保留，关联改变后原判定失效。
- 作业创建时保存名单快照，区分未交与卷面留白；修改之后的班级名单不追改历史分母。
- 显式支持单选、多选及旧选择题；集合比较接受常见分隔符与选项顺序变化，漏选、多选为错；单选参考不能包含多个选项。
- 修改题型、参考或原题，会使相应旧判定、解析、订正证据、画像与复习状态退出当前投影，历史记录不删除。

位置：core/identities.py；core/product.py；core/education.py；core/presentation.py；core/answer_keys.py。

## 2. 订正与教师反馈

学生可从答疑页或「订正与复习」提交文本、图片、PDF页图；每次提交生成新attempt，原答不覆盖。记录父作答、题目/参考/批改规则版本、独立性、提示与答案展示信息。PDF附件按既有渲染检查拆页，订正中保留页图；本入口不宣称同时保存学生上传PDF的原始二进制。

教师在作答详情「学生反馈」查看订正过程与附件，可做确定性的客观题参考比对，或手动复核并追加反馈。有已确认参考答案的客观题，在学生提交时即可由服务端自动比对，不要求每次复习都等待教师点击；证明题、缺参考或无法严格比较的答案仍需复核。学生不能写入教师结论，教师的新反馈通过共享课堂到达学生，其他学生看不到该记录。

位置：core/learning_records.py；core/learning_validation.py；ui/learning_hub.py；ui/product.py；core/collaboration.py。

## 3. 持久存储与API

启用MINDTRACE_DATABASE后使用标准库SQLite：

- 事务工作区快照为渐进兼容适配，保留已有业务对象，未一次性重写全部旧功能。
- record_index提供按学生/集合分页查询；job、调用预留、材料登记、迁移记录使用关系表与外键/唯一约束。
- 乐观版本检查防止陈旧页面覆盖新数据；JSON导入保留源文件，按内容hash去重，不覆盖已有同ID工作区。
- schema_migrations事务升级；已初始化连接只读检查版本，不在活动事务中重复执行DDL。发现更高数据库版本时拒绝降级写入。
- 后端对课堂访问码进行角色/学生范围校验。新功能使用类型化命令；旧页面保留有权限检查、版本和三方合并的同步适配器。
- 前端可以设置MINDTRACE_BACKEND_URL，经HTTPS访问独立后端；本机允许127.0.0.1/localhost的HTTP。访问码仅在请求头中传递，不放进URL。
- 独立API路径的图片/原PDF按hash存储，登记staged/ready、归属和课堂总字节预算；本机课堂订正附件也登记学生归属。学生只能绑定自己的新附件；读取还要经过实际作答范围校验。

**边界**：当前仍有工作区聚合快照及旧容量保护，不把它称为已完成全量关系化、无限分页前端或企业多实例扩容。当前目标为小规模课堂、一个持久数据库主机，可有独立API和worker进程。

位置：core/repository.py；api/app.py；core/backend_client.py；core/classroom.py。

## 4. 独立后台批改

提交批改创建持久逐题quick/deep任务。worker独立运行，页面仅显示进度；页面断开不承担执行。幂等键绑定题目/参考/规则版本，deep另绑定具体quick结果。成功步骤与待教师复核的结果不重新消费。

SQLite原子领取与递增fencing token防止两worker重复提交结果；执行期间续租。过期、取消、题目换版、快速结果更新或教师先行确认后，晚到结果不能覆盖当前决定。结果、错题投影、下一阶段任务与任务状态在同一事务提交。

短时429、服务繁忙、网络/5xx故障进入next_retry_at等待；授权、余额、日预算等明确停止或阻塞。持久调用预留跨worker重启保留，每次实际尝试独立准入；失败且实耗未知不记录成零费用。SDK原有受控重试、截断紧凑重试仍保留在现有模型适配器中，因此并非已统一为只有队列一层重试；后续可继续收敛。

后台进程读取服务端环境配置，Key不进工作区、任务payload、日志或浏览器。使用现有模型提供商接口，不擅自换模型、追加付费套餐或默认转发材料给新提供商。

位置：core/background.py；core/repository.py；scripts/run_worker.py；ui/background.py。

## 5. 学习画像、记忆与FSRS

画像只统计当前有效的原答复核、订正、复习和可追溯变式验证；顶层练习与Agent嵌套练习按同一原则投影。缺少旧版本来源的历史不补造为“已掌握”。独立成功与借助帮助成功分开；AI未确认建议不作为正式能力事实。每条显示来源题目，隐藏无助于学生理解的原始UUID；可以打开相关原题继续辅导。

Agent获得同学生跨题有效证据，作为受限来源LEARNING_MEMORY；其他题目变化进入上下文版本键，避免继续复用过期策略。保留原有有界动作、数学工具、直接答疑及变式验证，不引入整套多Agent框架或向量数据库。

复习直接使用官方fsrs==6.3.3的Scheduler、Card、Rating、ReviewLog，保留完整配置、UTC时间与日志；界面按北京时间显示。调度由有效日志重放，可在改判/换版后退出旧证据；命令与每次作答去重。只有独立正确且具备教师或本地参考核验，才可记录为回忆成功；查看解析、AI一句“会了”、未判定不会自动推进。无Optimizer、无Torch、无冷启动个体参数训练；不把FSRS回忆估计称为综合数学能力。

位置：core/review_scheduler.py；core/learning_records.py；core/agent.py；ui/learning_hub.py。

## 6. 界面与恢复

新增「订正与复习」「学习画像」入口，教师作答详情承接订正反馈。错题本展示订正进展，可直接提交订正、查看反馈或加入复习计划；订正不改写原答判定与班级历史统计。桌面订正采用过程/答案与附件双栏，手机收敛为紧凑指标卡和单列。画像使用本地确定性图形，避免离线环境加载外部图表资源失败；不输出无来源能力百分比。

备份包含SQLite一致快照、原卷/订正页图、课堂凭据摘要及hash清单；排除API Key。缺失或损坏的已引用材料阻止标记为完整备份。恢复只写新目录，校验内容并重映射工作区存储位置，不覆盖当前数据。

位置：core/backup.py；scripts/manage_backup.py；assets/style.css。运行方式见[06 开发与恢复](06_development_and_recovery.md)。
